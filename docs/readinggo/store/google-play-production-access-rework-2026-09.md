# Google Play 프로덕션 액세스 재작업 — 2026-09

## 1. 목적

2026-09-04 프로덕션 액세스 거절 이후 비공개 테스트를 실제 참여·피드백·수정 증거 중심으로 다시 운영한다. 초대 발송 수나 Form 제출 수를 테스터 참여로 간주하지 않는다.

## 2. 확인된 기준선

- Play Console 상태: 비공개 테스트
- Play Console 표시 설치 사용자: 5명(2026-09-06 확인)
- 최초 신청: 2026-09-03
- 거절 통지: 2026-09-04
- 기존 신청 Form: 응답 27건, 유효 고유 Gmail 11개, 중복 15건, 형식 오류 1건
- 테스트 안내 메일: 고유 주소 12개 발송, 이 중 1개 배달 실패
- 같은 안내 스레드에서 확인된 사람 회신: 0건
- 신규 피드백 Form: [ReadingGo Android 비공개 테스트 피드백 — 2026년 9월 재테스트](https://docs.google.com/forms/d/e/1FAIpQLSek1Lg3CHGZ1B7ESk4lIvI3qVauPrXEfFNUdC0IBRWboEhYLA/viewform)

개인정보와 테스터 이메일은 저장소에 기록하지 않는다. Google Form·Play Console·Gmail에만 보관한다.

## 3. 이전 신청에서 고칠 점

1. `신청`, `초대`, `Play opt-in`, `설치`, `14일 유지`, `핵심 기능 수행`, `피드백 제출`을 서로 다른 상태로 관리한다.
2. Play Console이 집계한 참여자만 14일 요건의 모수로 사용한다.
3. 실제 응답·이슈·수정 PR로 연결되지 않은 피드백을 신청 답변에 쓰지 않는다.
4. 12명을 최소 통과선으로만 보지 않고 이탈을 고려해 15명 이상을 목표로 모집한다.
5. D0는 Play Console에서 12명 이상이 유효 참여로 표시된 날이다. 초대 발송일이나 Form 제출일이 아니다.

## 4. 상태 모델

각 테스터는 비공개 관리표에서 다음 상태를 순서대로 가진다.

`applied → invited → opted_in → installed → active_day_14 → feedback_submitted`

- `applied`: 신청 Form 제출
- `invited`: 테스트 참여·설치 링크 발송 성공
- `opted_in`: Play Console에서 비공개 테스트 참여 확인
- `installed`: Google Play 설치 또는 업데이트 확인
- `active_day_14`: D0부터 14일 동안 참여 유지
- `feedback_submitted`: 전용 피드백 Form 제출

GitHub에는 개인별 상태를 올리지 않고 집계와 익명화된 피드백·이슈 연결만 기록한다.

## 5. 테스터가 수행할 핵심 기능

1. Google Play 비공개 테스트 참여 후 최신 버전 설치
2. 책 검색
3. 책 추가 또는 서재 확인
4. 페이지 진도 기록
5. 한 문장 저장
6. 회고 저장
7. 저장 기록 다시 확인
8. 가능하면 공유 기능 확인
9. 전용 피드백 Form 제출

모든 사용자가 모든 기능을 매일 수행할 필요는 없다. 다만 14일 동안 실제로 앱을 사용하고 최소 한 번의 구체적인 피드백을 제출해야 한다.

## 6. 증거 계약

재신청 전 아래 증거를 준비한다.

- Play Console 참여자 수와 14일 충족 화면 캡처
- 비공개 테스트 release와 기간
- 전용 Form의 고유 응답 수
- 익명화한 피드백 요약
- 피드백별 GitHub issue 또는 `검토 후 미반영` 결정
- 반영한 변경의 PR·commit·검증 결과
- 미해결 P0/P1 목록

`초대 메일을 보냈다`, `지인이 사용했다고 말했다`는 단독 증거로 쓰지 않는다.

## 7. 재신청 gate

다음을 모두 충족하기 전 재신청하지 않는다.

- [ ] Play Console 유효 참여자 12명 이상
- [ ] 이탈 대비 모집 목표 15명 이상
- [ ] D0부터 14일 연속 요건 충족
- [ ] 실제 설치·업데이트 확인
- [ ] 고유 피드백 12건 이상
- [ ] 각 피드백을 issue·PR·미반영 결정 중 하나로 추적
- [ ] 미해결 P0 0건
- [ ] 최신 release에서 핵심 기능 smoke 확인
- [ ] 신청 답변의 모든 문장을 증거로 역추적 가능

## 8. 실행 순서

4. 최신 비공개 release 설치 가능 여부 확인

### D0–D13

1. 핵심 기능 사용 요청
2. 설치·로그인·저장 차단 문제는 즉시 P0로 기록
3. 중간 점검으로 참여 이탈 확인
4. 피드백 Form 제출 요청

### D14 이후

1. Play Console 14일 충족 확인
2. 피드백 dedupe 및 익명화
3. issue·PR·미반영 결정 연결
4. 최신 release 재검증
5. 신청 답변을 실제 증거만으로 다시 작성
