### 8.13 결정 (2026-06-24, 배포 안전 — 카나리 + 피처 플래그 채택. dev-val-prod 3환경 기각. 충돌 시 §8.12 위에 **우선**)

> 배포안전 에픽(#897) P3 방향 결정. 런칭 후 개발 중 **'머지 = 즉시 100% 프로덕션'**으로 사고가 날 위험을 줄이는 방법으로, **엔터프라이즈식 dev-val-prod 3환경 승격 파이프라인을 검토했으나 기각**하고 **카나리(점진 배포) + 피처 플래그**를 채택한다.
> 근거: 3인·소비자 앱·Cloudflare Workers 규모엔 3환경이 과하다 — (a) 별도 val 환경은 prod와 어긋남("val에선 됐는데 prod 터짐") (b) 환경 유지 비용 (c) 매 릴리스 사람 게이트 = 속도 마찰(spec-first 2-PR이 묻힌 것처럼 안 지켜질 위험). 카나리는 *실제* 트래픽 일부로 검증해 어긋남이 없고, Workers gradual deployment라 거의 공짜에 사람 게이트가 필요 없다.

| 항목 | 결정 |

| 기각 | 엔터프라이즈 dev-val-prod 3환경 승격 파이프라인 — 현 규모 과함(나중 구체적 필요 시 재검토) |

| 문장·개인정보 | 공개 문장만 나뭇잎 본문으로 표시. 비공개 문장의 내용·존재·개수, `my_note`, 재키 대화, 개인 감상 원문은 타인에게 노출하지 않음 |
| 문장 길이·저작권 위험 | 공개범위와 무관하게 한 문장 원문은 최대 **1,000자**. OCR·직접입력·배치/import 모두 공백 제거 후 1~1,000자를 실제 저장할 수 있어야 하며, 1,001자 이상은 저장 시 앞 1,000 Unicode 문자로 일관되게 절단하고 사용자에게 비차단 경고를 표시한다. 글자 수 때문에 문장을 제외하거나 `private`로 강제하지 않는다. #1424의 공개 200자 제한은 OCR 기술 한계가 아니라 공개 인용 최소화 정책 제안으로 도입됐으나 이 결정과 후속 구현 #1457로 대체한다. 공개 문장의 누적·pagination을 통한 원문 재구성 위험은 인지하되 현재 서비스가 해당 콘텐츠 자체로 부가가치를 영위하지 않는다는 제품 판단 아래 이번 v17 출시 차단 조건으로 두지 않고, 별도 법무·제품 검토로 연기한다. 출처표기·삭제요청·seed provenance 의무는 유지 |
| 전환 | **4-B 확정**. 기존 사용자는 사전 고지 후 친구 책나무를 자동 활성화하고 언제든 전체 opt-out 가능. 신규 사용자도 같은 기본값을 쓰되 온보딩·설정에서 공개 사실과 해제 방법을 고지. 철회·차단은 피드·검색·캐시·직접 URL에 즉시 전파. **5-A 확정**으로 제한 view/RPC와 신규 앱을 먼저 배포하고 최소 지원 버전 미만을 업데이트 안내 후 차단한 뒤 broad base RLS를 소유자 전용으로 축소하며, 보안 rollback으로 broad RLS를 복원하지 않음 |

#### v17.5 같이읽기·미결정

- 상위 기능명은 **같이읽기**, 개별 공간명은 **읽기방**으로 한다. `숲`, `정원`, `마을`처럼 책나무 외의 새 공간 세계관을 추가하지 않는다.
- 책나무 탭 아이콘은 Lucide 공식 `book-open`·`sprout`·`tree-deciduous` 1차 시안을 #1453에 팀 공유했으며 **최종 선택 보류**다. 실제 20px·24px, 선택/비선택, light/dark, Android 비교 후 팀 의견으로 확정한다.
- 캐릭터 표시명은 **보류**다. Judy·Jerome 논의, 후보 의도·권리/혼동 조사, 동일 조건 비교 전까지 `Jacky / 재키`를 유지하고 다른 v17 구현을 막지 않는다.

#### v18.2 서재 최소 계약

- `읽고 싶은 책`, `읽는 중`, `읽은 책`, `중단한 책`을 별도 화면으로만 강제 분리하지 않고 **하나의 연속된 책 흐름**에서 탐색한다.
- 상태는 포함·제외 필터로 조정한다. 특히 중단한 책처럼 보고 싶지 않을 수 있는 상태는 쉽게 opt-out할 수 있어야 한다.
- **검색·필터·정렬을 분리**한다. 검색은 내 서재 내부 탐색과 실제 책 카탈로그 검색·등록을 담당하고, 필터는 상태 포함·제외, 정렬은 승인된 기준의 오름차순·내림차순을 담당한다.
- 좌우로 빠르게 flick해도 표지가 비거나 뒤늦게 튀지 않도록 현재 카드 주변의 표지·메타데이터를 사전 로드한다. 동시에 전체 도서를 무제한 DOM에 렌더하지 않는 bounded rendering을 유지한다.
- 제스처만 강제하지 않고 버튼·키보드·정확한 검색 목록을 대체수단으로 제공한다.
- 책을 넘기는 동작만으로 홈의 활성 책을 변경하지 않는다. 활성 책 변경은 명시적 동작으로만 수행한다.
- carousel의 포함 상태 기본값, 정렬 기준, 유한/순환 여부, preload window·pagination 수치는 구현 전에 비교 시안과 성능 검증으로 승인한다.

### v18.5 — 서재 flick·프로필 월간 활동 (#1520, 2026-08-25)

> Hyu가 `기존 카드 가로 스냅 + 월간 달력 + 페이지/문장 활동일`을 선택했다. 이 절은 v18.2의 carousel 세부 미정과 v18.3의 4번째 명칭·활동일·달력 미정을 대체한다.

- 3번째 서재는 기존 상태 탭·정렬·별점 필터가 만든 책 카드를 유한한 가로 `scroll-snap` 레일로 보여준다. 다음 카드 일부를 노출하고 터치·트랙패드·가로 휠·키보드를 지원한다. 무한 loop·복제 카드·넘기기만으로 활성 책 변경은 하지 않는다.
- 0권 빈 상태와 1권 단일 카드는 유지한다. 새 cache·권위 데이터는 만들지 않으며, windowing·pagination·preload 수치는 실제 대량 지연 증거가 생길 때 별도 승인한다.
- 4번째 탭 이름과 route는 **프로필** / `profile`로 유지하며 기존 프로필 제어를 보존한다.
- 월간 활동일은 `reading_sessions.session_date`와 본인 `sentences.created_at`의 사용자 로컬 날짜 합집합이다. 같은 날 여러 기록은 하루로 중복 제거하며 원천 수정·삭제 뒤 다시 계산한다.
- 기본은 이번 달, 주 시작은 일요일, 이전·다음 달을 탐색하되 미래 달은 비활성화한다. 현재 연속일과 선택 월 최장 연속일은 비징벌적 보조 요약으로만 표시하며, 오늘 미활동 중에는 어제까지 이어진 연속일을 유지한다.
- 이 slice에는 책 표지·대표 책·일별 상세를 넣지 않는다. XP·둥지·성·방패·만회·불꽃 보상도 복원하지 않는다.
- 기존 `sessions.calendar(days)`와 이미 로드된 내 문장 projection을 사용하므로 DB schema·migration·RPC·workflow는 변경하지 않는다.
