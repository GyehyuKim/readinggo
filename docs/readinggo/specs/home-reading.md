# 홈·독서 기록 — 활성 스펙

> **상태**: v18 활성 계약. `둥지/nest` 제품 개념과 활성 파일명은 #1535로 퇴역했다.
> 과거 XP·성장·성·스트릭·전용 탭 계약은 이 파일에 보존하지 않는다. 감사가 필요하면 Git history,
> archive 문서, 닫힌 이슈·PR, 적용 migration을 확인한다.
> **변경 원칙**: 이번 결정은 이름과 소유권 정리이며 사용자 동작을 재설계하지 않는다.

## 5. 홈 독서 계약

### 5.1 용어·route·호환 경계

| 개념 | 활성 정본 |
|---|---|
| 홈 독서 화면 | 사용자 라벨 **홈**, canonical route `home` |
| 한 번의 읽기·쪽수 기록 | **독서 세션**, 저장 테이블 `reading_sessions` |
| 저장 문장과 문장별 생각 | **문장 기록**. 현재의 중립적인 사용자 카피는 그대로 둘 수 있다 |
| 서재 | 사용자 라벨 **서재**, canonical route `library` |

- 과거 URL·history state·영속 내비게이션 입력의 `nest`와 `nest-grow`만 단일 정규화 경계에서
  각각 `home`과 `library`로 즉시 바꾸는 임시 alias로 허용한다.
- 정규화 뒤 앱 상태와 새 URL, history, 저장값, 사용자 카피, 접근성 이름, 로그·분석 이벤트에는
  canonical 값만 생성한다. alias를 다시 출력하거나 새 호출부에 확산하지 않는다.
- 구현 PR은 활성 module·component·test·workflow 파일명과 식별자에서 퇴역 이름을 제거한다.
  적용 migration과 DB 감사·rollback에 필요한 레거시 객체·데이터의 물리 삭제는 별도 DB 게이트다.
- 구 APK, 제거된 API, XP 기반 제품 모델을 호환 대상으로 유지하지 않는다.

### 5.2 홈과 활성 책

- 홈은 `status='reading'`인 활성 책 한 권의 표지·제목·현재/전체 쪽수와 진척을 보여준다.
- 권위 값은 `users.active_user_book_id`와 `DataStore.activeBook` 계약이다. 읽는 중 책이 여러 권이면
  기존 화살표·점·스와이프 조작으로 선택하며 모든 조작은 같은 전환 경로를 사용한다.
- 새 책을 `reading` 상태로 등록하면 그 책을 활성화한다. wish·완독 등록과 대량 서가 복원은
  활성 책을 가로채지 않는다.
- 활성 책을 중단·완독·삭제하면 남은 `reading` 책으로 승계하고, 없을 때만 `null`로 둔다.
- 책 전환은 다른 책의 쪽수·세션·문장·초안을 초기화하거나 합치지 않는다. 책별 기록은
  `user_book_id`로 분리한다([backend.md §7.8](./backend.md)).
- 책 카드의 기존 상세 진입과 소유 여부 라우팅, 책 정보 편집 동작은 유지한다.

### 5.3 진도와 독서 세션 저장

- 홈의 페이지 업데이트와 인라인 독서 종료는 기존 `DataStore.sessions.addToday` 경로를 사용한다.
  로그인 경로는 `checkin_atomic`으로 `user_books.current_page`와 당일 `reading_sessions`를 원자 저장하고,
  게스트 경로는 같은 DataStore 계약을 보존한다([backend.md §7.2](./backend.md)).
- `session_date`는 사용자 로컬 `YYYY-MM-DD`다. 같은 날 여러 번 저장해도 세션·활동일을 문장 수만큼
  부풀리지 않는다. `duration_sec`은 실제 독서시간이 있을 때만 누적한다.
- 페이지 전용 저장과 문장 저장은 독립 동작이다. 페이지 저장 실패가 문장 초안을 지우거나,
  문장 저장 실패가 입력 페이지·원문을 지우면 안 된다.
- 문장에 입력한 페이지는 `sentences.page`에 그대로 보존한다. 문장 페이지가 현재 진도보다 앞서도
  허용하며, 문장 저장으로 진도를 뒤로 밀지 않는다.
- XP·보상·상실·전용 성장 상태를 계산하거나 쓰지 않는다. 최근 리듬과 누적 성장일 표시는
  [systems.md §6.0](./systems.md)의 비징벌적 계약을 따른다.

### 5.4 문장 기록과 정확한 저장 행

- 문장 기록은 활성 `user_book_id`에 `DataStore.sentences.add`로 저장한다. 원문, 페이지, 책 귀속,
  공개범위와 기존 문장별 액션을 보존한다.
- 홈의 현재 중립 카피 `내가 남긴 흔적`은 #1535의 제거 대상이 아니다. `문장 기록`은 스펙 개념명이며
  별도 사용자 노출 개명을 요구하지 않는다.
- 저장 성공은 영속 readback이 반환한 실제 sentence ID와 행을 기준으로 한다. 임시 ID나
  문장 문자열·책·시각 조합으로 방금 저장한 행을 추정하지 않는다.
- 단일 문장 저장 성공에서만 정확한 저장 행에 `내 생각 덧붙이기`와 `재키와 대화하기`를 연결한다.
  `내 생각`은 기존 `my_note`/`DataStore.sentences.setNote`를 사용하고 기존 Q/A 블록을 보존한다.
- 페이지 전용 저장, 여러 문장 배치 저장, readback 실패에는 단일 행 성찰 행동을 노출하거나 실행하지 않는다.
- 중복 제출을 막고, 실패 시 원문·페이지·생각 입력을 그대로 유지해 재시도할 수 있게 한다.
- 문장 목록의 정렬·좋아요·삭제·재키·책 상세 이동과 현재 중립 카피는 동작 변경 없이 유지한다.

### 5.5 OCR 현재 계약

- 카메라·앨범 입력은 클라이언트 크롭 뒤 동일출처 Worker `POST /api/ocr`로 보낸다. OCR secret은
  서버에만 두고 클라이언트·응답·로그에 이미지, raw OCR, 문장 원문을 추가 노출하지 않는다.
- 이미지는 8MB 이하이며 EXIF 방향을 정규화하고 긴 변을 2560px로 제한한다. 단발 흐름은
  크롭 → 추출 중 피드백 → 전체화면 검토·편집 → 저장 순서다.
- 검토 화면은 추출 원문과 페이지를 사용자가 편집할 수 있게 하며 저장 전에는 DataStore나 홈 초안에
  OCR 결과를 쓰지 않는다. 취소·뒤로가기·`Escape`는 OCR 임시값만 폐기한다.
- 문장은 공백 제거 후 1~1,000 Unicode 문자다. 1,001자 이상 원문은 편집 중 보존하고 절단 예정임을
  알린 뒤 저장 시 앞 1,000문자만 저장한다. 글자 수를 이유로 공개범위를 바꾸지 않는다.
- 공개범위는 저장 시점의 계정 `default_sentence_visibility`를 adapter가 적용한다. OCR 화면은
  문장별 공개범위·책·감상을 별도로 바꾸지 않는다.
- 저장 중 중복 요청을 막고, 실패하면 검토 원문과 페이지를 유지한다. 성공은 실제 저장 행을 받은 뒤에만
  홈 문장 기록에 반영한다.
- 앨범 다중 선택은 사진 순서대로 성공 결과를 보존하고 실패 경계 너머 문장을 합치지 않는다.
  일부 실패 시 성공분과 실패 장 수를 알리고, 전부 실패하면 기존 초안을 유지한다.
- 오류·분석은 원문·이미지·정확한 책 식별자를 보내지 않는
  [analytics.md §3.1.1.1](./analytics.md#3111-ocr-이벤트-계약-1498)을 따른다.

### 5.6 저장 완료 후 행동

- 완료 화면의 첫 책임은 저장 성공과 실제 저장 결과 확인이다. 같은 수치를 보상 카드로 반복하지 않는다.
- 단일 문장 저장 성공이면 `내 생각 덧붙이기`, `재키와 대화하기`를 정확한 저장 행에 연결한다.
- `내 생각` 저장 성공 시 입력칸과 저장 버튼을 완료 결과로 교체하고, 저장한 생각을 같은 화면에서
  다시 보여준다. 작은 상태 문구만 바꾸거나 이미 끝난 저장 행동을 계속 노출하지 않는다.
- 생각 저장 뒤 1차 행동은 `다음 문장 기록하기`, 종료 행동은 `홈으로 돌아가기`다.
  `재키와 대화하기`와 `저장한 문장 보기`는 보조 행동으로 유지한다.
- 생각을 남기지 않은 일반 완료 상태에서도 다음 문장 기록·홈 복귀·저장 문장 확인 행동을 제공한다.
- 긴 저장 문장은 완료 창의 제한 높이 안에서 터치·키보드로 세로 스크롤해 전체 내용을 확인할 수
  있어야 하며, 화면 밖으로 잘린 채 접근할 수 없는 텍스트가 없어야 한다.
- 각 행동은 저장 mutation을 다시 실행하지 않는다. 완료 화면과 Companion을 동시에 겹치지 않고
  브라우저·Android 뒤로가기의 overlay 순서를 보존한다.
- 완독의 기존 별점·소감 흐름과 게스트의 계정 저장 제안은 일반 완료 행동으로 대체하지 않는다.
- 저장 실패에는 완료 화면을 열지 않고 입력을 보존한다.

### 5.7 데이터·개인정보 불변식

1. 책·진도·독서 세션·문장·생각·공개범위·게스트 기록은 이름 전환으로 손실되거나 확대되지 않는다.
2. 모든 데이터 접근은 DataStore를 경유하고 로그인 identity는 서버가 검증한다.
3. 신규 문장은 계정 기본 공개범위를 쓰며 알 수 없는 값은 `private`로 축소한다. 게스트 이관은
   저장 당시 공개범위를 보존한다([backend.md §7.2](./backend.md)).
4. 문장·생각·OCR 원문과 이미지, 사용자·책 식별자를 분석 이벤트나 오류 메시지에 넣지 않는다.
5. 저장 실패·부분 실패는 성공처럼 표시하지 않고 입력을 보존한다. UI의 낙관 행은 readback 뒤 권위 행으로 교체한다.
6. 이름 전환은 DB schema·migration·RLS·공개범위·OCR 엔진·사용자 행동을 새로 설계하는 근거가 아니다.

### 5.8 구현 PR 수용 기준

- canonical 홈 route와 새 출력은 `home`이며, legacy 입력 alias는 단일 정규화 경계 밖에서 발견되지 않는다.
- 활성 파일·module·component·test·workflow 이름, 사용자 카피, 접근성 이름, 주석, 분석 정의에
  퇴역 제품명이 남지 않는다. 허용 예외는 Git/archive/닫힌 이슈·PR/적용 migration과 입력 alias 경계뿐이다.
- 홈의 활성 책 전환, 페이지·세션 저장, 문장 저장·정확한 행 성찰, OCR, 완료 후 행동과 뒤로가기가 유지된다.
- 게스트와 로그인 경로 모두에서 책·진도·세션·문장·생각·공개범위가 보존되고 중복 저장이 없다.
- 정적 전체 추적 파일 검색은 허용 예외와 우발적인 활성 참조를 구분해 보고한다.
