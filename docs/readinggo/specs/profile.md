### 5.8.0 v18 서재·개인 활동 방향

#### 3번째 탭 — 서재

- 권위 데이터는 `user_books`·`wish_books`·`sentences`다. 읽고 싶은 책·읽는 중·읽은 책·중단한 책을 별도 화면으로만 강제 분리하지 않고 **하나의 연속된 책 흐름**에서 탐색한다.
- 상태는 포함·제외 필터로 제어한다. 중단한 책처럼 보고 싶지 않을 수 있는 상태는 쉽게 opt-out하고 다시 포함할 수 있어야 한다.
- 검색·필터·정렬의 책임을 분리한다.
  - 검색: 내 서재 내부 탐색과 Supabase canonical 책 카탈로그 검색·등록
  - 필터: 네 상태의 포함·제외
  - 정렬: 승인된 기준의 오름차순·내림차순
- 네 상태 포함·제외 필터와 정렬이 만든 단일 책 projection을 **중앙 선택 표지 + 주변 상단부 탐색 레일**로 렌더한다. 선택된 책 한 권은 표지 전체·제목·상태·진척을 중심에 표시하고, 같은 projection의 앞뒤 책은 표지 상단을 둥근 조각으로 가로로 연속 노출해 한 화면에서 여러 권의 존재를 체감하게 한다. 주변 조각을 탭하거나 레일을 좌우로 탐색하면 해당 책이 중앙 선택으로 이동한다. 터치·트랙패드·가로 휠·좌우 화살표 키로 같은 유한한 시작·끝에 도달하며 세로 페이지 스크롤을 가로채지 않는다.
- 네 상태는 기본으로 모두 포함하고 사용자가 각 상태 chip을 눌러 포함·제외한다. 0권은 검색·등록 빈 상태를 유지하고 1권은 주변 레일 없이 중앙 책 한 권만 표시한다. 2권 이상도 무한 loop나 복제 카드를 만들지 않으며, 중앙 선택이 필터·정렬 결과에서 사라지면 남은 projection의 첫 책으로 안전하게 이동한다. 브라우저 이미지 로딩을 재사용하고 새 preload window 수치는 실제 지연 증거 전 도입하지 않는다.
- 주변 조각 탐색은 `active_user_book_id`를 바꾸지 않는다. 중앙의 전체 표지를 탭할 때만 기존 소유 여부 라우팅으로 책 상세를 연다. 활성 책 변경은 상세의 명시적 행동으로만 수행한다.
- 기존 책 카드 디자인·책 상세·등록·가져오기는 재사용할 수 있으나, 상호배타적 상태 탭과 상태별 그리드는 통합 projection의 포함·제외 filter로 대체한다. 3번째 서재와 4번째 화면에 같은 서재를 중복 렌더하지 않는다.
- 기본 포함 상태는 네 상태 전체다. 새 schema 없이 기존 필드만 사용해 사용자 책은 완독 행의 `completed_at` 또는 그 밖의 `started_at`, 관심 책은 `created_at` 최근순으로 정렬하며 존재하지 않는 수정 시각을 추정하지 않는다. 제목·별점 정렬은 오름차순·내림차순을 제공하고 값이 없는 항목은 해당 정렬의 뒤에 둔다. 대량 도서에서 실제 지연이 측정되면 windowing·pagination과 preload 범위를 별도 성능 결정으로 승인한다.

#### 4번째 탭 — 프로필 월간 활동 캘린더

- 사용자 라벨과 canonical route는 기존 **프로필** / `profile`을 유지한다. 닉네임·소개·팔로워/팔로잉·좋아요·내 문장 진입·프로필 편집·관리자 도구의 기존 소유권도 유지한다.
- 프로필에는 사용자 로컬 기준 월간 활동 캘린더를 둔다. 기본은 이번 달이며 이전/다음 달로 이동할 수 있고 미래 달 이동은 비활성화한다. 주 시작은 일요일이며 달 밖의 날짜는 빈 셀로 표시한다.
- 활동일은 이미 사용자 로컬 `YYYY-MM-DD`인 `reading_sessions.session_date` 문자열과 본인 `sentences.created_at` 타임스탬프만 사용자 로컬 날짜로 변환한 값의 합집합이다. `session_date`를 JS `Date`로 다시 파싱·변환하지 않는다. 같은 날 여러 페이지 기록·문장이 있어도 활동일 1일이며, 원천을 다시 읽어 과거 수정·삭제를 재계산한다.
- 현재 연속일과 선택한 달 안의 최장 연속일을 보조 요약으로 표시한다. 오늘 아직 활동이 없으면 어제까지 이어진 연속일을 유지하고 오늘 활동이 생기면 즉시 연장한다. 빈 날·연속 중단을 실패·손실·경고로 표현하지 않고 XP·둥지·성·방패·만회·불꽃 보상 UI를 복원하지 않는다.
- 날짜 셀은 활동 여부를 브랜드 색과 접근성 라벨로 함께 전달한다. 이 slice에서는 책 표지·대표 책·하루 여러 책 상세를 넣지 않으며 별도 결정 전 임의 규칙을 만들지 않는다.
- 캘린더 로딩 실패는 프로필 전체를 내리지 않고 해당 영역만 안전한 빈 상태로 둔다.

#### 유지할 개인정보·보안 계약

- 내 프로필과 새 사용자 표면에 `XP`, `Lv.`, 완성 둥지 수, 스트릭 단절 수치를 되살리지 않는다.
- 서재의 책(`user_book`)마다 `public|private`를 설정하고 모든 현재·미래 문장과 생각이 상속한다. 신규 책·unknown은 private다. 문장별 선택이나 계정 문장 기본값은 없다.
- 타인 프로필은 공개 책과 그 허용 기록만 보여준다. private 책의 존재·개수·본문·생각·개인 활동은 노출하지 않는다. 기존/게스트 기록 이관은 [backend.md §7.0.2](./backend.md)의 비손실·동의 근거·보수적 축소를 따른다.
- 폐기 예정 전용 제한 RPC/RLS와 broad base RLS 축소는 UI 보류와 분리된 보안 계약이다. broad 정책을 보안 rollback으로 복원하지 않는다.

#### 수용기준

1. 하단 3번째 사용자 라벨은 `서재`이며 canonical route는 `library`다.
2. 네 책 상태를 하나의 흐름에서 보고 상태별 포함·제외와 정렬을 적용할 수 있다.
3. 0권이면 carousel을 만들지 않고 검색·등록 CTA가 있는 빈 서재를 보여준다.
4. 1권이면 한 권을 중앙에 표시하고 이전·다음·flick·loop를 비활성화해 가짜 이동이나 index 오류를 만들지 않는다.
5. 2권 이상은 다음 카드 일부가 보이는 유한 가로 레일이며 실제 권수·시작·끝을 보존한다. 대량 지연이 측정되면 별도 성능 결정 없이 임의 수치의 preload·windowing을 추가하지 않는다.
6. 제스처 없이도 같은 책에 도달하고 검색·상세·활성 책 변경을 수행할 수 있다.
7. 기존 책·문장·진도·세션·위시 데이터와 공개범위가 손실되거나 확대되지 않는다.
8. 4번째 프로필은 월간 활동 캘린더, 현재 연속일, 선택 월 최장 연속일을 표시하며 페이지 세션·문장 저장일을 로컬 날짜 기준으로 합친다.
9. XP·둥지·성·방패·하루 만회와 은퇴한 책나무 표면·route·flag·전용 API·analytics가 임시 콘텐츠로 부활하지 않는다.

#### 5.8.1 성(🏰)과 읽은 책 분리

- **역사적 성 개수**: 당시 `users.xp`에서 파생한 값이다. v18 활성 제품 지표가 아니며 신규 구현 근거로 사용하지 않는다.
- **성 노출**: 1,600 XP 경계 통과 세리머니와 둥지 주기 정보에서 표시한다. 별도 성 선반이나 완독 책 기반 성 카운터는 두지 않는다.
- **읽은 책**: `user_books(status='completed')`를 표지·별점·소감·완독일과 함께 읽은 책 탭에 전시한다. 전체 공개 정책은 유지한다(§5.8.2).
- **정렬/필터 (#513·#795)**: 읽은 책 탭에서 최근순(기본)·별점순·제목순 정렬과 **별점 다중선택 필터**를 제공한다. ⭐ 필터 버튼(활성 개수 배지) → **바텀시트**: `★5·★4·★3·★2·★1·무평점` 다중선택(OR), **즉시 반영 + 초기화 + 완료**. 버킷 = 정수 floor(`4.5→★4`, `0.5~1.x→★1`), `무평점`은 **1급 옵션**(OCR 임포트 등 무평점 대량 유입 대비). 빈 선택 = 전체. (구 `⭐4점 이상` 단일 토글 대체)

- **내 서재 목록 3열 그리드화**: 현재 탭의 책 목록을 표지 중심 3열 그리드(표지 아래 제목 작게)로 표시하며, 탭 시 기존 `BookDetailModal`로 진입한다.
- **읽는 중 카드 라벨 (#1224)**: 표지 아래 상태 라벨은 **진행률 `현재쪽/전체쪽` 형태**(예 `23/320쪽`, 0쪽 포함) — 전체 쪽수 미상일 때만 "읽는 중". 구 "미완독" 라벨은 읽는 중 책에 오해 소지가 있어 제거. 완독(별점/완독)·중단(중단) 라벨은 기존 유지.
- **탭별 문장·감상 노출**: 책 목록 아래에 "💬 이 책들의 문장·감상" 섹션을 두고, 현재 탭에 속한 책들의 저장 문장만 최신순으로 표시한다.
- **다른 사람 책장 구경 가능** (전체 공개 정책). 타인 한 문장은 [feed.md §5.7.1](./feed.md) 페이지 블라인드 적용
- **타인 프로필 = 전체 페이지 (v7.2, #3·4·5)**: 피드 @닉 탭 → 풀스크린 프로필. ① 헤더(닉·완독/읽는중/스트릭/XP·팔로우 버튼) ② **책장 6권+더보기**(읽은/읽는중 필터 토글) ③ **❤️ 읽고 싶어하는 책**(대상 user의 `wishlist_public=true`일 때만 노출 — [feed.md §5.7.2](./feed.md)) ④ 공개 한 문장. **책 카드 탭 → 그 사람의 그 책 평점·후기·한 문장 드릴다운**(`users.bookContrib`). DataStore: `users.publicShelf`/`users.publicWishlist`/`bookContrib` ([backend.md §7.2](./backend.md))
- 관심 책 추가: 소셜 피드 한 문장 → 책 상세 → "관심 책에 추가" (`DataStore.wishBooks.add`)
- **책 중단 동선 (#593)**: 읽는 중 책의 상세(`BookDetailModal`)에서 **"읽기 중단"** → `DataStore.myBooks.abort(ubId)` → status='aborted'. 중단 책은 "읽는 중"·"완독"에서 빠지고 **"중단" 탭**으로 이동한다. 진척(`current_page`)은 보존되어 "다시 읽기"(`resume`) 시 그대로 이어진다. **`resume`은 status='reading' 갱신에 더해 그 책을 활성 책(`active_user_book_id`)으로 승계**(#1203) — 홈이 즉시 이 책을 띄우고 새로고침 후에도 '읽는 중'에 남는다(중단 탭에 잔류하지 않음). 양 어댑터 동일. 중단은 **삭제가 아니며**(책장에서 사라지지 않음) 완독 카운트·XP 주기에 영향 없다.
- **책 완전 삭제 동선 (#1195, Edgar 피드백)**: 잘못 담은 책을 되돌릴 수 없게 **영구 삭제**. 책 상세(`BookDetailModal`)에 중단과 **구분되는 3차 danger 텍스트 버튼 "이 책 삭제"** → `DataStore.myBooks.remove(ubId)`. 모든 상태(읽는 중·중단·완독)에서 노출된다. **확인창은 기록 유무를 알린다**: 한 문장이 N개 있으면 "한 문장 N개도 함께 삭제…", 문장 없이 읽은 진척만 있으면 "읽은 기록도 함께 삭제…", 아무 기록도 없으면 단순 확인. 삭제 시 그 책의 문장·세션도 함께 사라진다(Supabase는 `sentences`·`reading_sessions` FK `on delete cascade`, localStorage는 `user_book`에 내포). **활성 책을 삭제하면 남은 reading 책으로 active 승계**([home-reading.md §5.2](./home-reading.md#52-홈과-활성-책)) — 홈이 빈 상태로 떨어지지 않는다. 중단(되돌리기 가능)과 삭제(영구)는 별개 액션이다.
- **책 완독 시 active 승계 (#1217)**: 활성 책을 완독(`DataStore.myBooks.complete` → status='completed')하면 그 책이 활성으로 남지 않게 **남은 '읽는 중' 책으로 active 승계**(없으면 null) — abort(#643)·resume(#1203)·remove(#1195)와 같은 불변식(`active_user_book_id` 는 항상 reading 책 또는 null). 누락 시 완독책이 활성으로 남아 홈이 완독책을 '읽는 중'으로 계속 띄우고 완독 탭에도 동시 노출되던 버그. 양 어댑터 동일. **DB 강제(#1217 재발 후, `45_active_book_invariant.sql`)**: 클라 픽스는 구버전 탭·APK를 못 덮어 재발 → 불변식을 트리거로 강제(status 이탈 시 자동 승계 + active 를 non-reading 으로 쓰는 시도 교정). JS 승계는 게스트(localStorage)·즉시 UI 용으로 유지.

#### 5.8.3 완독 별점 + 소감 (v7 신설)

완독 세리머니 직후 입력하는 역사적 as-built 계약:
- **별점** 0.5~5, **0.5 단위(반별점)** (선택, `user_books.rating`) — 별 탭은 정수, 별 좌측 절반 탭은 0.5
- **별점 접근성**: 선택 전 5개 별도 패널 배경과 **3:1 이상 비텍스트 대비**로 식별되어야 한다. 각 별 터치 영역은 최소 **44×44px 수준**이며, 키보드 포커스 윤곽과 선택값(`aria-checked`)을 제공한다.
- **완독 소감** 텍스트 (선택, `user_books.review_text`)
- 완독 목록·다른 사람 책장에 표시

#### 5.8.4 책 상세 / Export

- **정보 계층과 순서 (#1264)**: 책 상세(`BookDetailModal`)은 다음 네 구역을 위→아래로 고정한다. ① 헤더(표지·제목·저자/출판사) ② 상태별 Primary(상태·핵심 CTA) ③ Secondary(한 문장 추가·목록) ④ Tertiary(책 소개·추천·AI 결과). 모달을 처음 열었을 때 헤더와 Primary가 한 화면에 보여야 하며, Secondary보다 Tertiary를 먼저 두지 않는다.
- **상태별 헤더 직하 Primary**:
  - **읽는 중**: 진도 바(`현재/전체쪽`, `%`; 쪽수 미상은 `N쪽 읽음 · 쪽수 미상`) → 바로 아래 같은 행에 **`완독으로 표시`(1차)** / **`읽기 중단`(2차)** 2열 CTA. 현재 진도가 0쪽이어도 상태와 두 CTA는 생략하지 않는다.
  - **중단**: `중단 · N쪽에서 멈춤` 상태 요약 → 전체 너비 **`다시 읽기`(1차)**. 진도는 보존됨을 짧게 알리고 완독/중단 CTA는 숨긴다.
  - **완독**: 완독일(있을 때) + **0.5 단위 별점**을 헤더 바로 아래 항상 노출한다. 별점 미입력도 빈 별과 `별점 남기기`를 보여 입력 가능성을 드러낸다. 소감은 한두 줄 미리보기 + **`소감 남기기`/`소감 수정`(2차)** 진입만 두며 textarea를 본 모달에 인라인 전개하지 않는다.
  - **공통**: `이 책 삭제`는 핵심 상태 CTA와 떨어진 3차 danger 텍스트 액션이며 Primary로 승격하지 않는다. 상태별로 존재하지 않는 액션을 비활성 표시하지 않고 숨긴다.
- **Secondary — 내 기록**: `한 문장 추가`를 먼저, 목차 설정과 한 문장 목록을 그 다음에 둔다. 여러 문장 붙여넣기·사진 가져오기는 한 문장 추가의 보조 진입점으로 묶는다. `전체` 타임라인은 날짜 내림차순이며 페이지/문장/`my_note`와 기존 스포일러 블라인드 계약을 유지한다. 목차가 있으면 아래 #1627 분류 보기를 추가하되 문장 행 자체를 복제·이동하지 않는다.
- **Tertiary — 더 알아보기**: 한 문장 영역 뒤에 책 소개, 이 책 같이 읽는 숲, 함께 읽으면 좋은 책, 완독 후 AI 카드(재키 회고·다음 책·추출 책)를 둔다. 데이터가 없거나 해당 상태가 아니면 기존 조건대로 섹션을 생략한다. 길이가 큰 설명·추천은 기본 접힘을 허용하되, 접힘 제목과 펼침 상태를 접근성 API에 전달한다.
- **Compact utility row**: 교보문고 외부 링크와 `내 한 문장 Markdown 내보내기`를 Tertiary 하단의 작은 아이콘+텍스트 한 행으로 통합한다. 각 항목은 독립된 버튼/링크이고, Markdown은 한 문장이 있을 때만 노출한다. 공간이 부족하면 항목 단위로 줄바꿈하되 텍스트를 말줄임하거나 아이콘만 남기지 않는다.
- **완독 소감 bottom modal**: `소감 남기기/수정` 탭 시 책 상세 위에 별도 bottom modal을 연다. 제목(`완독 소감`), 책 제목, 현재 소감이 채워진 최대 1,000자 textarea, 글자 수, `취소`와 **`저장`(1차)**을 제공한다. 저장 중 중복 제출을 막고, 성공하면 책 상세의 미리보기를 즉시 갱신한 뒤 bottom modal만 닫는다. 실패하면 입력을 보존한 채 열린 상태에서 오류를 알린다. 바깥 탭·닫기·뒤로가기로 미저장 내용이 있으면 폐기 확인을 거친다. 키보드가 올라와도 입력과 저장 CTA가 가려지지 않고, 닫은 뒤 포커스는 진입 버튼으로 돌아간다. 별점 편집은 헤더 직하에서 유지하며 이 소감 modal 안에 중복 배치하지 않는다.
- **쪽수 미상 graceful (v7.2, #204)**: `total_pages`가 없으면(알라딘 itemPage 누락) 진척률 0·"쪽수 미상" 표기(1쪽=100% 버그 방지). 등록 시 BookInfoModal에서 **총 쪽수 수동 입력**(선택) 가능. *외부 교보 API는 무료 공식 소스 부재로 미채택 — 수동 폴백으로 대체*
- **한 문장 사후 감상**: 별도 작성한 내 생각(최대 1,000자)은 본인만 추가·편집하고 현재 부모 책 공개를 상속한다. 이 문서의 감상 `my_note` 표기는 [backend.md §7.0.1](./backend.md)의 분리된 공개 가능 생각 필드를 뜻하며, 비공개 AI 대화·미분리 레거시 혼합 노트는 공개 대상이 아니다. 공개 책에서는 기존·새 생각 모두 공개되며 인용과 구분한다. 입력 옆에 책 상태와 `이 책의 문장과 내 생각은 공개돼요` 또는 `나만 볼 수 있어요`를 알린다. 원문도 공개 상태와 무관하게 1~1,000자이며 글자 수가 공개를 바꾸지 않는다. 사후 편집은 `DataStore.sentences.setNote`를 사용한다.

##### 개인 판본 목차·챕터별 문장 회고 (#1627)

**공통 상세와 기본 보기**

- 별도 완독 전용 화면을 만들지 않는다. `status='reading'`과 `status='completed'` 모두 같은 `BookDetailModal`, 같은 `user_book_id`, 같은 `DataStore.chapters.list/replace`와 같은 페이지 분류 함수를 사용한다. 중단 책도 기존 상세에서 기록을 잃지 않으며 목차가 있으면 같은 읽기 보기를 사용할 수 있다.
- 목차가 한 행 이상인 완독 책은 상세 진입 시 `챕터별`을 기본 선택한다. 읽는 중·중단 책은 `전체`가 기본이다. 어느 상태든 사용자가 바꾼 현재 모달의 선택은 모달이 열린 동안 유지하되 책을 바꾸면 상태별 기본값에서 다시 시작한다.
- 목차가 없으면 상태와 무관하게 기존 `전체` 최신순 타임라인을 기본·유일한 기록 보기로 유지하고 `목차를 설정하면 챕터별로 볼 수 있어요`와 소유자용 `목차 설정` 행동을 제공한다. 문장이 0개여도 목차 설정은 가능하다. no-TOC 때문에 문장 추가·편집·삭제·좋아요·공개범위·공유·내보내기 동작을 숨기거나 바꾸지 않는다.

**목차 설정·붙여넣기 검토**

- 소유자 책 상세의 내 기록 구역에서 `목차 설정`을 열며, 현재 행을 `제목 / 시작 페이지 / 깊이`로 편집하고 추가·삭제·재정렬할 수 있다. `position`은 화면 순서에서 0부터 다시 만든다. 재정렬은 drag만 요구하지 않고 각 행의 위/아래 이동 버튼과 키보드 동등 조작을 제공한다.
- 첫 버전의 빠른 입력은 **여러 줄 붙여넣기 → 행 변환 → 검토·편집 → 저장** 순서다. parser는 원문을 바로 저장하지 않는다. 각 비어 있지 않은 줄을 하나의 후보 행으로 보이고 제목·시작 페이지를 추출하며, 앞쪽 들여쓰기는 검토 가능한 depth 후보로만 사용한다. 페이지를 해석하지 못한 줄·중복 줄·빈 제목은 조용히 버리지 않고 해당 행의 오류로 남긴다.
- 검토 표에서 모든 제목·시작 페이지·depth를 수정할 수 있고 변환 결과 개수와 오류 개수를 알린다. `1 미만`, 정수 아님, 알려진 판본 총 쪽수 초과, 시작 페이지 중복·역순, 첫 행 depth 0 아님, 앞 행보다 두 단계 이상 깊어짐을 저장 전에 해당 행과 요약 live region에 표시한다. 저장 버튼은 오류가 0일 때만 활성화한다.
- 저장은 전체 행을 한 번에 `chapters.replace(userBookId, rows)`로 교체한다. 저장 중 중복 제출을 막고 성공은 권위 readback의 전체 행이 일치한 뒤에만 표시한다. 실패·응답 미확정이면 편집 중인 모든 행과 기존 저장본을 보존하고 재시도/재조회를 제공한다. 미저장 변경이 있는 닫기·뒤로가기는 폐기 확인을 거치며 성공 뒤 진입 버튼으로 포커스를 돌린다.
- OCR, 목차 사진 인식, 외부 목차 API 자동 수집, AI 챕터 요약·감상 생성, Notion 동기화는 이 범위에 없다.

**문장 보기·중첩 count**

- 목차가 있으면 `전체 / 챕터별 / 페이지 미입력 / 목차 밖`을 텍스트가 있는 tablist 또는 동등한 단일선택으로 제공하고 각 보기에 실제 count를 붙인다. `페이지 미입력`은 `page_missing`, `목차 밖`은 `outside_toc`이며 둘 다 추측 배정하지 않는다. `sentences.page=null`은 표시·편집 전후 그대로 보존한다.
- `전체`는 기존 날짜 내림차순 flat timeline 정본이다. `챕터별`은 `position ASC` 목차순으로 문장이 있는 챕터를 보여주고 각 챕터 안은 `page ASC, created_at ASC, id ASC`로 안정 정렬한다. 결과가 0이면 목차 골격을 긴 빈 목록으로 강제하지 않고 `이 목차에 연결된 문장이 없어요`와 다른 보기 행동을 제공한다.
- depth는 제목 들여쓰기와 접근성 heading level/목록 계층으로 함께 표현하며 색·여백만으로 부모/자식을 구분하지 않는다. 각 행은 자기 직접 범위의 문장 수를 표시한다. 부모는 연속 하위 행을 합친 `전체 N개` aggregate도 별도로 표시해 direct count와 혼동하지 않는다. 하위 문장이 부모 aggregate에 포함되더라도 화면 전체 문장 합계와 `전체` count에는 한 번만 센다.
- 챕터 제목을 접고 펼칠 수 있으나 목차 순서와 count는 바뀌지 않는다. 긴 제목은 200% 텍스트 확대와 320px급 폭에서 의미 있는 전체 텍스트에 접근 가능해야 하고, 13개 챕터·100개 이상 문장은 모달 내부 세로 스크롤과 Android 뒤로가기/overlay 순서를 깨지 않는다.
- 타인이 공개 책 상세를 볼 때는 [backend.md §7.0.7](./backend.md#707-개인-판본-목차와-조회-분류-계약-1627)의 `book_public_allowed` 최소 RPC 결과만 사용한다. 편집 행동은 소유자에게만 보이며 private·unknown·권한 실패에서 목차 존재나 count를 빈 상태와 다른 오류로 누출하지 않는다.

**구현 수용 기준**

1. 정상: 읽는 중과 완독의 동일 모달, 완독 기본 `챕터별`, 네 보기 전환, 경계 페이지 재분류, nested direct/aggregate count, 문장/목차 결정적 순서를 확인한다.
2. 오류: 목록/replace 실패, 응답 유실, malformed paste, 행 validation, 문장 분류 실패는 기존 저장본·입력·선택을 보존하고 성공/빈 상태로 위장하지 않는다. 목차 load만 실패하면 문장 `전체`는 계속 보이고 `목차를 불러오지 못했어요. 다시 시도해 주세요.`를 해당 영역에 표시한다.
3. 빈 상태: 목차 없음, 목차만 있고 문장 없음, `page_missing`만 있음, `outside_toc`만 있음, 특정 챕터 0개를 구분한다. 목차 없음은 기존 flat `전체` 동작과 CTA를 유지한다.
4. 권한: owner 편집, 공개 책의 익명/로그인 독자 읽기, private/unknown/blocked/suspended/임의 UUID 거부, 책 삭제 cascade 뒤 재진입을 검증한다.

#### 5.8.8 한 문장 모아보기 (v7.1, #171)
홈 문장 기록의 "전체 N개 보기" → 모달. **전체 / 책별 / 좋아요** 필터 + **읽었음 누적 카운터**. 문장 탭 → 책 정보(BookInfoModal). 홈의 활성 계약은 [home-reading.md §5.4](./home-reading.md#54-문장-기록과-정확한-저장-행)을 따른다.

- **내 한 문장 → 책 상세로 이동 (v7.5, #439, 프로필에서 제거)**: 프로필 본문의 "내 한 문장" 섹션(최신 10개 + "더 보기")은 제거. 내 한 문장은 **프로필 → 내서재 → 읽고 있는 책 클릭 → 책 상세**(BookDetailModal)에서 그 책의 문장 + 참새 대화 기록과 함께 확인한다(companion.md §3). 좋아요 필터는 이 §5.8.8 모달에서 계속 확인 가능.
- **좋아요(❤️) 스탯 탭 → 좋아요한 문장 목록 (#510→#641)**: 프로필 stats row 의 `❤️ 좋아요 N` 을 탭하면 이 모달이 **'좋아요' 필터로 열린다**(`RG_openCollection({filter:'fav'})`). 좋아요 필터는 내 문장뿐 아니라 **내가 좋아요한 타인 문장까지 포함** — `claps.list()` 의 sentence 임베드를 내 문장 목록에 머지(타인 문장은 책 제목·페이지·문장 표시). 빈 상태: "아직 좋아요한 문장이 없어요 · 소셜 탭에서 마음에 드는 문장에 ❤️를 눌러보세요". (#641: ~~책갈피~~ 폐기, stats 라벨·식별자 모두 `좋아요`/`claps`로 단일화)
- **내 한 문장 검색 (v9 신설, #1007)**: 모아보기 모달 상단(필터 탭 아래)에 **검색 입력창**. 내 문장이 쌓이면(읽었음 수십~백 개) 스크롤로는 특정 문장을 못 찾으니 키워드로 즉시 좁힌다 — 모은 문장이 검색 가능한 **개인 독서 위키**가 되는 첫 단계(김문 님 피드백).
  - **범위 = 내 문장만** (`listMine()` 결과). 타인 공개 문장·전체 검색은 비대상(별도 기능 + 저작권 #1008).
  - **매칭 = 정규화 substring**(소문자·공백 정리한 부분일치). 대상 필드: 문장 `text` + 감상 `note`(my_note) + 책 제목 `bookTitle` + 저자 `author`. 퍼지(Fuse) 대신 substring — 한글에서 예측 가능하고 오매칭이 없다. 규모(유저당 ≤약 100문장, [backend.md sentences])라 **클라 필터로 즉시·오프라인**, 백엔드/검색 인덱스 불필요.
  - **기존 필터와 합성(AND)**: 검색어는 전체/책별/좋아요 탭 위에 겹쳐 적용한다(예: '책별' + 검색 → 책별 그룹 안에서 매칭만, 매칭 0인 책 그룹은 숨김). 빈 검색어 = 현행 동작 그대로.
  - **상태·문구**: 입력 즉시 반영(클라 동기 — 디바운스 불요). 매칭 0 → "검색 결과가 없어요". placeholder = "내 문장·감상·책 검색".
- **내 문장에게 묻기 — 독서 위키 Q&A (v10 신설, #1007)**: 같은 모달 상단에 **찾기 ↔ 🤖 내 문장에게 묻기** 모드 토글. '묻기'는 키워드 검색이 못 잡는 질문 — "내가 외로움에 대해 모은 문장?", "이 문장들 관통하는 주제?", **"다른 책에서 비슷한 생각 한 부분?"**(책 가로지르기, 여인채 님 아이디어 #919) — 에 LLM이 답한다. 검색이 *위치*라면 묻기는 *해석·연결*. 김문 님 피드백("LLM에게 질문도")의 실현.
  - **범위 = 내 문장만** (`listMine()` 결과, 검색과 동일 풀). 타인·전체 문장은 비대상. 문장 0개면 '묻기' 토글 미노출(비활성).
  - **그라운딩(환각 가드 핵심)**: 답은 **내가 모은 문장들에만 근거**한다. 워커 system 프롬프트가 (1) 근거 문장·책 제목을 함께 밝히고 (2) 문장에서 못 찾으면 지어내지 말고 정확히 "모은 문장에서는 못 찾았어요"라고만 답하며 (3) 문장에 없는 사실·다른 책 내용을 새로 만들지 않도록 강제한다. RAG/임베딩/벡터DB 불필요 — 규모(유저당 ≤약 100문장 ≈ 2-3K 토큰)라 **내 문장 전체를 한 프롬프트에 통째로** 넣어 **질문당 1콜**(Gemini Flash 텍스트, 무료 티어). 호출 경로·계약은 [backend.md §7.9.2](./backend.md).
  - **프라이버시**: 내 문장→LLM 전송은 재키 companion(`/api/companion`)이 이미 하는 선례와 같은 서버리스 프록시 경로(키 서버 보관, 클라 노출 0). **내 문장만** 보내므로 타인 발췌 수집/저작권(#1008) 위험은 낮다.
  - **UI·상태**: 질문 입력(textarea, ⌘/Ctrl+Enter 전송) + 보내기 → 로딩("문장을 살펴보는 중…") → 답 표시(근거 문장/책 포함). 첫 진입 시 **예시 질문 칩**(위 3종)으로 무엇을 물을 수 있는지 안내. 호출 실패 시 "답하기 실패 — 잠시 후 다시", 미설정(데모)이면 안내 문구. `wiki_ask` 이벤트 트래킹(문장 수·질문 길이).
  - **비대상(보류, #1007 후속)**: 자동 주제·소재 태깅/클러스터링, 전체(타인 공개) 검색. ('묻기'가 모은 문장에 한해 LLM 탐색을 이미 제공하므로 자동 태깅은 별개 후속.)
