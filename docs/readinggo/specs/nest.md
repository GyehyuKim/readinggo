### 5.1 홈 탭 — 화면 구성

홈 탭(하단 탭 라벨 '홈', 내부 탭 키 `nest`)은 **책읽기 중심**으로 구성된다(v8, #432·#436). 활성 책 1권의 진척 배너 아래 읽기 세션을 인라인으로 펼치고, 오늘 남긴 한 문장을 바로 보여준다. (구 The Path 경로 시각화는 v7에서 폐기. **둥지 캐릭터(NestTheatre)는 v8부터 홈이 아닌 [profile.md §5.8](./profile.md) 최상단**에서 렌더된다.)

| 요소 | 동작 |
|---|---|
| 상단 바 | **현행 레거시**: 🐦 로고 / `XP {n} · 🪺 둥지 {floor(totalXp/1600)}개` / 도서 찾기. **v18 목표**: XP·완성 둥지 수와 레거시 진입을 제거한다. 중립적인 책·문장 요약은 유지할 수 있으나 서재와 중복되는 제어를 새로 넣지 않는다. 구 수치의 제거는 [systems.md §6.0](./systems.md)을 따른다 |
| **책 진척 배너** | 활성 책 진척률 % + 미니 진척 바 + 책 표지·제목·현재/전체 페이지 (책 단위 — 둥지와 별개, #313). 제목 행 우측 ⚙️는 해당 책의 정보 편집 진입점 |

#### 5.1.1 일반 기록 완료 — 다음 행동 (#1561)

- 화면의 첫 책임은 **저장 성공 확인**이다. 제목·저장 개수·방금 저장한 문장 미리보기는 유지하되 같은 수치를 별도 보상 카드로 반복하지 않는다.
- **단일 문장 저장 성공**에서는 방금 저장한 문장을 이어 해석하는 행동을 먼저 제공한다.
  1. **내 생각 덧붙이기** — 완료 화면 안에 감상 textarea와 저장 버튼을 직접 제공한다. 별도 화면을 한 번 더 열지 않고 방금 문장의 `my_note`에 저장하며, 기존 재키 Q/A 블록이 있으면 보존한다. 저장 성공은 입력칸 가까이에서 알리고, 실패하면 입력을 그대로 유지해 재시도할 수 있게 한다.
  2. **재키와 대화하기** — 완료 화면을 닫고 기존 문장별 Companion을 `jacky` 모드로 열어 방금 문장을 대화 맥락으로 사용한다.
- 생각 입력과 재키 대화는 저장 mutation이 성공하고 readback에서 **정확한 sentence ID**를 받은 뒤에만 활성화한다. 문장 문자열·책·시각으로 대상을 추정하지 않는다. 페이지 기록만 저장한 경우, 문장이 둘 이상인 배치 저장, readback 실패에는 문장별 성찰 입력·행동을 표시하거나 실행하지 않는다.
- 후속 독서·자산 행동은 성찰 행동 아래에서 유지한다.
  1. **이 책에서 계속 기록하기** — 완료 화면을 닫고 현재 책의 한 문장 입력으로 돌아가 스크롤·포커스한다.
  2. **저장한 문장 보기** — 완료 화면을 닫고 현재 책의 저장 문장 영역으로 이동해 방금 문장을 확인한다.
  3. **내 서재로 가기** — 완료 화면을 닫고 canonical `library` route로 이동한다.
- 성찰 진입은 기존 `DataStore.sentences.setNote`·Companion 대화 저장 경로를 재사용하며 새 문장·세션 mutation을 만들지 않는다. 완료 화면과 Companion을 동시에 겹치지 않고, 진입 시 완료 화면의 복원 history를 정리한다.
- 단순 종료는 상단 닫기 또는 뒤로가기로 제공할 수 있으나, 큰 1차 버튼을 `닫기`만으로 사용하지 않는다. 각 행동은 저장 mutation을 다시 실행하지 않는다.
- 완독에서는 기존 별점·소감 저장이 1차 책임이며 위 일반 행동으로 대체하지 않는다. 게스트의 `이 기록, 계정에 저장하기` 제안도 유지한다.
- 저장 실패에는 완료 화면을 열지 않고 초안·페이지를 보존하는 기존 계약을 유지한다. 공유·친구초대는 매 저장 후 상시 노출하지 않는다.

### 5.2 현행 레거시: 둥지 진화 — 1,600 XP 주기

> **v17 상태**: 아래 §5.2~§5.2.2는 `origin/main@39248ef`와 구 APK의 동작을 설명하기 위해 보존한다. 새 제품 계약은 §5.0이며 이 모델로 새 기능·지표를 만들지 않는다.
> **v8.1 변경 (2026-06-15, #520)**: 전체 누적 XP를 그대로 단계에 매핑하는 모델을 대체했다.
> 둥지는 책과 분리된 XP 기반 시각화라는 원칙은 유지하되, **1,600 XP마다 성을 완성하고 새 둥지 주기를 시작**한다.

XP 값은 차감 없이 계속 누적한다([systems.md §6.3](./systems.md)). 둥지 표시만 현재 주기 값으로 계산한다.

```text
cycleXp     = totalXp % 1600
castleCount = floor(totalXp / 1600)
```

| 단계 | 현재 주기 XP | 이모지 | 단계명 | 색상 | 배경색 |
|---|---:|---|---|---|---|
| 1 (시작) | 0–99 | 🌿 | 나뭇가지 자리 | #AFAFAF | #f3f4f6 |
| 2 | 100–399 | 🪹 | 빈 둥지 | #F59E0B | #FEF3C7 |

| 4 | 900–1,599 | 🐣 | 다정한 집 | #1CB0F6 | #EFF6FF |
| 5 (경계 연출) | 1,600 도달 순간 | 🏰 | 참새의 성 | #CE82FF | #FAF5FF |

> 이모지는 토스트·세리머니 문구 등 텍스트 표면용. 화면 단계 아이콘은 `nestArt`(커스텀 SVG, #719). 둥지·새 테마로 통일(#756) — lv4 SVG는 집 → 부화 새끼.

- Lv5는 **1,600 XP 달성 시 도달하는 주기 완료 단계**다. 성 획득 후 현재 주기 XP는 `0`이 되고 둥지는 Lv1부터 다시 시작한다.
- 책을 바꾸거나 완독해도 `totalXp`와 현재 주기는 유지된다. 완독 자체는 성 획득 트리거가 아니다.

**진척 표시 = "절대 주기 XP / 다음 단계 임계값" 기준 (#743 — #682 갱신).** 진척 바·수치는 전체 주기(`cycleXp / 1600`)도, 단계-상대(`intoXp / spanXp`)도 아니라 **현재 주기 누적 XP를 다음 단계 임계값에 견준 절대값**으로 계산한다. 숫자와 바가 같은 기준이라 시각적으로 일치한다.

```text
stage   = getNestStageByXp(totalXp)         # 현재 단계
next    = 다음 단계 (없으면 최고 단계)
표시 숫자 = cycleXp / next.minXp            # 절대 누적 XP / 다음 단계 진입 임계값
bar pct  = cycleXp / next.minXp * 100       # 숫자와 동일 기준
```

- 예) 빈 둥지(100–399) 구간에서 `cycleXp=342` → `342 / 400 XP` (86%). 따뜻한 둥지(`cycleXp=471`) → `471 / 900 XP` (52%).
- **왜 #682(단계-상대)를 갱신했나**: 단계-상대는 `471`인데 화면에 `71 / 500`으로 나와 상단 XP(471)와 어긋났다(#743). 절대 기준은 상단 XP와 일치하고 숫자·바가 한 기준이라 직관적이다.
- **최고 단계 예외**: 다음 임계값이 없으면(`next=null`, `isMax`) **"최고 단계"**로 표기(`pct=100`). 실서비스에서는 1,600 경계가 곧 Lv1로 리셋되므로 방어적 처리.
- 공유 헬퍼 `nestStageProgress(totalXp)` → `{ stage, next, intoXp, spanXp, pct, isMax }` (data.js)는 그대로 두되, **표시 기준은 `cycleXp / next.minXp`** 다(nest.js `_absPct`/`_cycleXp`가 국소 계산). `intoXp/spanXp/pct`는 잔여 XP 문구 등 보조에만 쓴다. NestTheatre·체크인 세리머니 진척 바가 공통으로 절대 기준 사용.

#### 5.2.1 성(🏰) — XP 주기 완료 지표

- **성 개수 = `floor(totalXp / 1600)`.** 별도 DB 컬럼이나 테이블 없이 `users.xp`에서 파생한다([backend.md §7.2/§7.3](./backend.md)).
- **획득 시점 = XP 추가 후 1,600 경계 통과.** Lv5 도달 세리머니 후 다음 주기를 시작한다.
- 완독 책은 [profile.md §5.8](./profile.md)의 읽은 책 목록에 그대로 남지만, 더 이상 성 개수나 성 카드로 환산하지 않는다.
- XP 차감이 없으므로 획득한 성은 줄어들지 않는다.

#### 5.2.2 전용 둥지 탭 — 최소 성장 설명 계약 (#1308)

전용 둥지 탭(`nest-grow`)은 사용자가 별도 계산 없이 아래 세 가지를 한 화면에서 확인하게 한다. 홈 TopBar는 전체 **XP {n} · 🪺 둥지 {n}개**를 요약하고, 이 탭은 현재 주기 단계·다음 성장·완성 이력을 상세히 보여준다.

| 질문 | 필수 표시 | 계산·동작 계약 |
|---|---|---|
| 지금 어디인가 | `N번째 둥지` + 현재 단계명·단계 그림 | `N = floor(totalXp / 1600) + 1`, 단계는 `cycleXp`의 기존 0/100/400/900 임계값으로 계산 |
| 다음에는 무엇이 되는가 | 현재 단계 옆 다음 단계명·그림 + `cycleXp / next.minXp XP` 진행 바 + `다음 단계까지 R XP` | `R = next.minXp - cycleXp`. Lv4의 다음은 **둥지 완성**이며, 1,600 XP 경계 뒤 새 둥지가 Lv1부터 시작한다고 같은 표면에서 설명 |
| 지금까지 무엇이 남았나 | `완성된 둥지 C개` + `둥지 완성` 탭의 1번째부터 C번째까지 누적 이력 | `C = floor(totalXp / 1600)`. 0개도 숨기지 않고 첫 둥지까지의 진행을 표시하며, 완독 권수와 섞지 않음 |

- `둥지가 자라는 법` 안내는 기존 다섯 단계·임계값과 “활동 → XP → 둥지 성장 → 1,600 XP에서 완성 → 새 둥지 시작”만 설명한다. 새 화폐·보상·미션을 덧붙이지 않는다.
- 단계·다음 성장·완성 수는 모두 `users.xp`에서 파생하며 별도 저장 상태를 만들지 않는다. 새로고침·책 전환·완독 뒤에도 같은 `totalXp`에서 동일한 결과가 나와야 한다.
- 현행 참새·둥지 단계 그림을 유지한다. 조류 거부감 대응을 이유로 새 캐릭터나 캐릭터 선택 정책을 이번 범위에서 만들지 않는다.
- 출시 후에는 [analytics.md §3.1.3](./analytics.md)의 탭 진입·안내 열기·완성 이력 확인 이벤트를 주간으로 관찰한다. 목표치나 자동 판정선은 두지 않고, 이해가 어려운 단계·표면을 찾는 근거로만 쓴다.

### 5.3 활성 책 전환

여러 책을 동시에 읽을 수 있으나, **항상 한 권이 "활성 책"**.

- 활성 책 = 홈 탭이 그리는 책
- **새 책 등록 시 active 자동 전환 (#1196, Edgar 피드백)**: 새 책을 **'읽기 시작'(status='reading')** 으로 등록하면 그 책이 **자동으로 활성 책**이 된다 — 이전 책이 남아 유저가 캐러셀 화살표를 찾아 직접 바꾸던 문제 해소. 데이터층(`myBooks.add`)이 등록과 동시에 `active_user_book_id`를 새 `user_book`으로 지정한다(양 어댑터). **찜('읽고 싶어요')·완독 담기는 전환 대상 아님**(reading 만) — 찜은 `add`를 타지 않고, 완독 담기는 `add({status:'completed'})`. 대량 서가 복원(`addBatch`)도 `activate:false`로 마지막 책이 active를 하이재킹하지 않게 한다.
- **현재 구현 = 좌우 리볼빙 캐러셀 (#185, v7.2)**: 홈 책 카드에 `‹ ›` 화살표 + 하단 점 인디케이터. 읽는 중 책이 2권 이상이면 노출, 좌우로 넘겨 **즉시 활성 책 전환**. 전환 = `window.RG_activateBook` → `activeBook.set` + 둥지 재계산
- **좌우 스와이프 제스처 (#1001)**: 화살표 버튼과 **동일 전환 로직(`switchBook(dir)`)을 재사용**하는 터치·드래그 제스처를 책 카드에 추가(버튼은 접근성용으로 유지 — 제스처는 *대체가 아니라 추가*).
  - **방향**: **왼쪽으로 밀기 → 다음 책(`dir=+1`)**, **오른쪽으로 밀기 → 이전 책(`dir=-1`)**. 화살표(`‹`=−1·`›`=+1)·"내용이 손가락을 따라온다" 규칙과 일치.
  - **입력 통합**: Pointer Events(`onPointerDown/Move/Up/Cancel`) 하나로 모바일 터치 + 데스크탑 마우스 드래그 모두 처리. 마우스는 좌클릭만.
  - **임계치 ~45px**(`SWIPE_PX`) 넘으면 전환, 미만이면 **원위치 스냅백**. 8px(`SWIPE_SLOP`) 미만 이동은 탭으로 간주(오발동 방지).
  - **가로 우세일 때만 발동**(`|dx|>|dy|`): 첫 의미 이동에서 축을 잠가, **세로 우세면 제스처를 포기하고 페이지 세로 스크롤을 통과**시킨다. wrap `touch-action: pan-y`로 브라우저 세로 스크롤과 비충돌 보장. 가로 확정 후에만 `preventDefault`.
  - **드래그 중 모션**: 카드만 `translateX`로 손가락을 따라가되 0.6 저항 계수로 절제. 전환 확정/취소 시 `transform .2s ease-in-out`(DESIGN.md motion: short·move=ease-in-out, `transform`만 — 레이아웃 속성 금지)으로 스냅. 드래그가 실제로 일어났으면 카드 탭(책 상세 열기)을 1회 억제.
  - **책 1권 이하면 비활성**(스와이프 no-op, `touch-action: auto`로 복귀). 끝 책에서 더 밀면 `switchBook`의 모듈러 순환을 따른다(화살표 버튼과 동일).
- **각 책의 세션·진척·한 문장은 독립 보존**(책 전환 시 데이터 초기화 금지)
- 데이터: `users.active_user_book_id` ([backend.md §7.8](./backend.md)). 전환 = `DataStore.activeBook.set`
- **활성 책 중단/삭제 시 active 승계 (#643, #593 후속 · #1195)**: 활성 책을 중단(`status='aborted'`)하거나 **완전 삭제(`myBooks.remove`, #1195)** 하면 active를 `null`로 해제만 하지 않고, 남아 있는 `reading` 책으로 **자동 승계**한다(승계 대상 = 캐러셀 첫 책 = `myBooks.list` 순서 첫 reading). 남은 reading 책이 없을 때만 `null` 유지(빈 상태가 올바름). 미승계 시 홈이 "책 등록하기" 빈 상태로 떨어지던 회귀 차단. 삭제(Supabase)는 **행 삭제 전에** active를 승계해야 `active_user_book_id` FK가 `set null`로 떨어지지 않는다. 양 어댑터(localStorage / Supabase 의 `abort()`·`remove()`) 동일 보장.
- ~~구 설계: 표지/제목 탭 → 전환 **시트** 슬라이드업~~ → **캐러셀로 대체(시트 폐기, v7.2)**. 별도 `ActiveBookSheet` 컴포넌트 없음.

### 5.4 일일 미션 — [§4](./onboarding.md) D 참조

- 하루 1세션. 같은 날 재진입 시 "오늘은 이미 완료했어요" + 한 문장 추가 옵션(서브 액션, 스트릭·XP 영향 없음)
- 입력: 현재 페이지 + 한 문장(페이지 강제·문장 선택, **1000자 이내**). **그 문장이 속한 페이지로 기록**(진행률과 별개 개념 — "📍 N쪽의 문장")
  - **페이지 직접입력 편집 동작 (#686)**: 체크인 바텀시트의 페이지 직접입력 칸은 **빈 문자열·편집 중 부분값을 허용**한다. 매 키 입력마다 `0`으로 강제하거나 클램프하지 않아 백스페이스 삭제·커서 위치 편집이 정상 동작한다. 범위 클램프(`0 ~ book.total`)는 **블러/제출 시점**에만 확정한다.
- 완료 시 즉시 보상: XP +20 + 스트릭 +1 + 둥지 진척 갱신 ([systems.md](./systems.md))
- **체크인 세리머니 (v8 갱신, #449/#426)**: 스트릭 카드·"N일 연속" 문구 **제거** — 대신 **둥지 진척도 bar**(체크인 전→후 애니메이션)로 "오늘 한 쪽이 둥지를 키운다"를 보여줌. 둥지 단계가 오르면(`nestUp`) 별도 step의 **진화 축하 화면**(이전 단계 → 다음 단계 + 카피 + "계속 →")으로 전환
  - **진척 바 기준 = 현재 단계 구간 (#685, §5.2 헬퍼 재사용)**: 세리머니 진척 바도 `nestStageProgress`로 계산해 NestTheatre 표시와 일치시킨다. 하단 문구는 "성까지 N%" 대신 **다음 단계까지 남은 XP**(`{다음 단계명}까지 N XP`)로 안내한다.
  - **헤드라인 문구 분기 (#685)**: **페이지만 저장**(문장 미입력) 시 헤드라인은 **"책읽기 완료 +20 XP"**. **한 문장을 실제로 등록**한 경우에만 **"1개 문장 등록 +N XP"**. 페이지만 저장했는데 "문장 등록"으로 표기되던 거짓 문구 제거.
- **한 문장 보상 카드 정직 표시 (#549)**: 세리머니 보상 그리드의 한 문장 카드는 **문장을 실제로 남겼을 때만 `🔖 저장됨`**. 페이지만 업데이트(문장 미입력)했는데 "저장됨"이 뜨던 거짓 표시 제거 — 미입력 시 **이 책에서 모은 한 문장 수(`📖 N개 · 이 책 한 문장`)**, 0개면 **`✍️ 한 문장 남겨봐요` 독려**로 표시
- **완독 시(100%)**: 완독 세리머니 + 완독 배지 + Confetti(주기 완료 세리머니와 별개) → 별점·소감 입력([§5.8](./profile.md)). 완독 보상 XP가 1,600 경계를 넘긴 경우에만 별도의 성 획득 세리머니를 이어서 표시한다.
- **별점 UI**: 0.5~5점, **0.5 단위(반별점)** (#153). 별 전체 탭 = 정수점, 별 좌측 절반 탭 = 0.5점 (SSOT: [profile.md §5.8.3](./profile.md))
- 미기록: 스트릭만 위기(방패 없으면 리셋). **둥지·XP·성은 존속**(v7 — XP 차감 폐지, [systems.md §6.2/§6.3](./systems.md))

#### 5.4.1 마일스톤 회고 (v9, #938) — 서사로 고양감 증폭

게이미피케이션의 코어 감정은 '고양감(uplift)'이다. 점수·랭킹 같은 외적 보상은 과잉정당화로 내적 동기를 밀어내므로 **더하지 않고**, 이미 쌓인 **한 문장·순간**을 마일스톤에서 돌아보게 해 **숫자가 아니라 서사로** 고양감을 키운다. 완독 회고(참새, [companion.md](./companion.md) §4.1)와 별개 — 이쪽은 *전 기록을 가로지르는 내 흔적 타임라인*이다.

| 항목 | 규칙 |
|---|---|
| 트리거 (절제) | **완독** / **연속 7일** / **연속 30일** / **둥지 성(1,600 XP 주기 완료)** 도달 시. 체크인당 **1개만**(우선순위: 완독 > 성 > 30일 > 7일) |

| 노출 타이밍 | 체크인 세리머니가 **닫힌 뒤** 1개 (세리머니와 겹치지 않게). 본 흐름을 막지 않는 부가 연출 |

#### 5.4.2 한 문장 배치 입력 (#1198) — 여러 개 임시저장 후 한번에 기록

한 시간 읽으며 문장 ~10개가 떠올라도 **매 문장마다 짹(체크인 세리머니)이 뜨면 흐름이 끊긴다**(Edgar 피드백). 그래서 홈 한 문장 입력을 **여러 초안을 부담없이 쌓아두고 덮을 때 한번에 기록**하는 형태로 확장한다. 기존 단일 입력(초안 1개) 경로는 **그대로 유지**된다 — (+)로 자연히 커지는 확장이지 별도 모드가 아니다.

| 항목 | 규칙 |
|---|---|
| **(+) 초안 행** | 한 문장 입력창 아래 **(+) 문장 더 추가**(`rgIcon('plus')`, 2차 tonal)로 초안 입력 행을 늘린다. `drafts[0]`=기존 입력창(OCR·포커스 대상), `drafts[1..]`=추가 행(각 행 우측 **×** = `rgIcon('close')` 로 삭제). 항상 최소 1행 |
| **임시저장(미확정)** | 초안은 **`localStorage` 키 `rg_sentence_drafts:<bookId>`**(책별)에 저장돼 네비게이션·리로드에도 보존된다. **아직 DataStore 미기록**(확정 아님) — 게스트·로그인 **양 모드 동일 로컬 전용**. 확정(기록) 또는 모든 행이 비면 키 제거 |
| **공유 페이지** | 한 문장 툴바의 페이지 입력(`quickSentPage` = "덮을 때의 쪽")을 **배치 전체 공유 페이지**로 쓴다. 비우면 현재 진도(`current_page`). 각 문장 `sentences.page`에 이 값을 그대로 저장(#1202 — 진도보다 낮아도 입력값 유지) |
| **한번에 기록** | 커밋 버튼 라벨: 실내용 초안 **1개면 `남기기`**(기존 단일 경로 `handleCheckin({sentence})`), **2개 이상이면 `N개 한번에 기록`**(`handleCheckin({sentences:[{text,page}]})`) |
| **세리머니 1회** | 배치는 **체크인 세리머니를 1회만** 띄운다(문장 N번 아님). 헤드라인 = **`N개의 한 문장 기록 · +N쪽`**, 보상 카드 한 문장 값 = **`N개`**. 스트릭·XP·진도(`sessions.addToday`)·둥지 갱신은 **1회**(문장 수만큼 부풀리지 않음 — §5.8 "합산 1회, handleCheckin N회 금지"와 동일 정신) |
| **영속(양 어댑터)** | 커밋 시 `DataStore.sentences.add` 를 **문장마다 1회** 호출(공유 페이지) — 게스트(`datastore.js`, `_guest` 마킹 → 로그인 시 §7.7 일괄 이전)·로그인(`datastore-supabase.js`, Supabase insert) 동일 계약. 진도는 `max(현재, 공유쪽)` 로 **1회** 올림 |

- **비목표**: 초안별 개별 페이지 오버라이드(공유 페이지로 충분), 초안의 서버 동기화(확정 전까지 로컬 전용).

### 5.5 읽기 모드 (#184) — 몰입 독서 + 상시 한 문장 캡처

둥지는 *진입*에 좋지만 읽으며 한 문장 적기엔 부적합 → 별도 **읽기 모드**(북모리식 몰입 화면).

- 진입 (v8 갱신, #432): 홈 CTA **"📖 읽기 시작"** → **같은 화면(홈)에 인라인으로 펼침**. 별도 진입 화면(2depth)·풀스크린 전환 없음 — `inline` prop으로 ReadingMode를 홈 책 카드 아래 렌더
- **독서 타이머**: 상단 경과 시간(⏱). 일시정지/계속. 백그라운드 시 Page Visibility로 일시정지(근사 정확)
- **상시 한 문장 입력칸**: 화면에 항상 열려 있어 떠오른 문장을 즉시 저장(아카이브). 저장마다 `sessions.addToday`(당일 1회 idempotent — 체크인/스트릭 충족) + `sentences.add`
- **저장 = 토스트만 (#347/#438)**: 읽는 중 저장은 토스트(흐름 유지) + `[저장]` 버튼만 — 인라인 '💬 지금 대화' 제거. **읽기 종료 시 참새 자동 진입은 도입하지 않는다**(원 v7.4 안 #347 — 의존한 읽기모드가 #505로 폐기, 미출시. 2026-07-09 제거 결정, 스펙 삭제). 재키는 카드(내 흔적·책 상세·되감기·모아보기)에서 **수동 진입**만.
- **인용 ↔ 내 생각 토글 — 폐기 (#596, was #360/#381/#420)**: '내 생각'(thought) 개념 멸종. 생성·설정 진입점(책장·CompanionModal 토글, `estimateSentenceKind` 휴리스틱) 전부 제거, `DataStore.sentences.add` 는 `kind:'quote'` 고정, 기존 thought 행은 `27_extinct_thought.sql` 로 quote 전환. `sentences.kind` 컬럼은 롤백 안전상 유지하되 사실상 **quote 단일**.

**목표 레이아웃 정규화 계약 (#1467, 계획)**:

- **처리 순서**: Upstage OCR → 결정론적 레이아웃 정규화 → solar-pro3의 줄바꿈·띄어쓰기 보조 → 원문 충실도 검증 → 검토 화면. 결정론적 정규화는 Solar 성공 여부와 무관하게 항상 적용하며, Solar 실패를 raw 물리 행으로 폴백하지 않는다.
- **입력·행 재구성**: Upstage 응답의 `pages[].text` 행 순서와 `pages[].words[].boundingBox.vertices` 위치를 함께 사용한다. 전용 line 필드는 가정하지 않는다. 단어 좌표로 각 인쇄 행의 왼쪽 시작점·대표 행 높이를 구하고, 크롭 안의 우세한 본문 왼쪽 기준선을 계산한다. 임계값은 고정 픽셀이 아니라 페이지 폭·대표 행 높이에 정규화하며 실제 OCR fixture로 고정한다.
- **문단 경계**: 같은 본문 기준선에서 이어지는 단일 물리 줄바꿈은 공백 하나로 합친다. 앞 행이 문장 종결부호로 끝나고 다음 행이 본문 기준선보다 의미 있게 들여쓰기된 경우 실제 문단 시작으로 판정해 `\n\n`을 보존한다. 원래 `pages[].text`에 빈 줄이 있으면 좌표 판정과 무관하게 문단 경계로 보존한다.
- **좌표 폴백**: `words`·bounding box가 없거나, 행과 단어를 안정적으로 대응하지 못하거나, 좌표가 비정상인 경우 기존 빈 줄(`\n\n`)만 문단으로 보존하고 나머지 단일 줄바꿈을 공백 하나로 합친다. 이 경로에서 의미를 추정해 새 문단을 만들지 않는다.
- **원문 충실도 가드**: raw OCR과 Solar 후보에서 모든 whitespace만 제거한 문자열이 정확히 같을 때만 Solar 후보를 채택한다. 글자·숫자·문장부호의 변경·추가·삭제 또는 출력 절단이 하나라도 있으면 후보를 버리고 결정론적 결과를 반환한다. 채택한 후보에도 최종 레이아웃 정규화를 다시 적용한다.
- **응답·프라이버시**: 클라이언트에는 기존처럼 최종 `text`와 현행 상태 필드만 반환하고 raw OCR·단어 좌표·이미지·Solar 원문을 추가 반환하거나 로그에 남기지 않는다. 기존 OCR 오류 `code`/`stage`, 동일출처, 8MB 제한, 검토·편집 흐름을 유지한다.
- **저장 경계**: 이 정규화는 추출 결과의 레이아웃만 바꾼다. §5.6.1의 입력 중 원문 보존, 저장 시 앞 1,000 Unicode 문자 절단·안내, 공개범위 유지 계약을 우회하지 않는다. 윗첨자 각주 복원·각주 제거, 맞춤법·고유명사 교정, 표·목록·시·다단 일반화, OCR 엔진 또는 Document Parse 전환은 비목표다.
- **회귀 fixture**: 실제 한국어 책 사진 사례를 개인정보 없는 축약 OCR JSON으로 고정한다. 인쇄 18행에서 같은 문단의 행 끝은 합치되, 들여쓰기된 `메넬라오스는…`와 `그가 이런 것들을…` 앞의 경계를 보존해 3문단을 반환해야 한다. 좌표 없음·기존 빈 줄·Solar whitespace-only·Solar 원문 변경·Solar 절단·Solar 실패 fixture를 함께 검증한다.

#### 5.6.1 OCR 전체화면 검토·편집 흐름 (#1265, 계획)

OCR 전문이 홈의 작은 입력칸에서 잘려 보이고 원하는 구절을 골라내기 어려운 문제를 해결한다. 이 뷰는 **단발 OCR 결과 1건을 확인해 한 문장 1건으로 확정하는 임시 편집 화면**이며, 저장 전까지 `drafts`·DataStore 어디에도 OCR 텍스트를 쓰지 않는다.

> **상태**: #1457은 `origin/main@415917e`와 Production DB migration 53에 반영됐다. 아래 1~1,000자 저장·Unicode 절단은 현행 계약이며, #1474는 문장별 selector만 제거하고 길이 계약은 바꾸지 않는다.

**상태 흐름**:

```text
home
  → crop(file)                         사진 촬영/앨범 선택
  → extracting(blob)                   전체화면 로딩, 중복 요청 차단
  → review({ text, page, sourceBook }) 추출 성공
      ├─ save → saving → home          한 문장 저장 성공
      └─ cancel → home                 OCR 임시값 폐기

extracting 실패·빈 결과 → home         기존 실패 토스트, 검토 뷰 미진입
saving 실패 → review                    입력 보존 + 재시도 안내
```

| 항목 | 계약 |
|---|---|
| **진입** | §5.6의 카메라·앨범 → 크롭 → OCR이 비어 있지 않은 텍스트를 반환하면 자동 진입한다. 로딩 오버레이가 닫힌 뒤 검토 뷰를 열며, 기존 홈 `drafts[0]`에 OCR 결과를 프리필·이어붙이지 않는다. |
| **화면 구조** | 앱 셸 위를 덮는 전체화면 한 장: 상단 바 왼쪽 **취소**(3차 텍스트), 가운데 제목 **추출한 문장 확인**, 오른쪽 **저장**(1차 솔리드) → 본문 전체 높이를 쓰는 큰 `textarea` → 하단 페이지 입력. 홈 헤더·하단 탭은 가리고 검토 내용만 스크롤한다. |
| **편집 가능 필드** | (1) **한 문장 원문**: 추출 전문을 그대로 초기값으로 보여주고 자유롭게 선택·삭제·수정한다. 최종 저장값은 앞뒤 공백을 제거한 **1~1,000자**([backend.md §7.3](./backend.md#73-데이터-모델-관계형--phase-1-기준)); 현재 글자 수를 `N/1,000`으로 항상 보인다. 1,001자 이상도 입력 중에는 원문을 보존하며 카운터 옆에 `저장하면 앞 1,000자만 남아요`를 표시한다. 글자 수 때문에 공개범위를 바꾸지 않는다. 원문을 요약·재작성하지 않는다. (2) **페이지**: 숫자만 입력, 비우면 활성 책의 현재 페이지, 입력하면 `1..total_pages`로 제한한다. 현재 진도보다 앞선 페이지도 허용하고 문장 페이지에는 입력값을 보존한다(§5.4.2 공유 페이지 규칙). 책·감상·공개범위는 이 화면에서 편집하지 않는다. |
| **저장** | 공백 제거 후 빈 문자열이면 저장하지 않고 해당 필드에 오류를 연결해 포커스한다. 1,001자 이상은 Unicode 문자 기준 앞 1,000자를 기존 단일 `handleCheckin({ sentence, sentPage })`/`DataStore.sentences.add` 경로로 **한 번만** 저장하고, 성공 후 `1,000자를 넘어 앞부분만 저장했어요`를 비차단 메시지로 알린다. 확인 modal을 추가하지 않는다. 공개범위는 저장 시점의 계정 `default_sentence_visibility`를 adapter가 적용한다. 저장 중 버튼을 비활성화해 중복 등록을 막는다. 성공하면 OCR 임시 상태를 비우고 홈으로 복귀하며, 저장된 문장이 활성 책의 한 문장 목록에 즉시 보인다. 홈의 기존 초안과 페이지 입력값은 덮어쓰지 않는다. 저장 실패 시 검토 뷰와 편집값을 유지하고 재시도 가능한 오류를 알린다. |
| **취소·뒤로가기** | 상단 **취소**, Android/브라우저 뒤로가기, 하드웨어 키보드 `Escape`는 같은 종료 동작이다. OCR 텍스트·검토 페이지 임시값만 폐기하고 홈으로 돌아간다. DataStore·한 문장 목록·홈 `drafts`에는 변화가 없다. 자동저장이나 취소 확인창은 두지 않는다. |
| **재진입** | 취소·저장 뒤 새 사진을 선택하면 새 검토 상태로 시작한다. 직전 OCR 결과는 복원·누적하지 않는다. |

**접근성·모바일 제약**:

- 검토 뷰는 `role="dialog"`, `aria-modal="true"`, 접근 가능한 제목을 갖는다. 진입 시 원문 `textarea`로 포커스를 이동하고, 닫을 때 OCR을 시작한 카메라/앨범 버튼으로 복귀한다. 포커스는 열린 동안 검토 뷰 안에 머문다.

- `100dvh`/`--app-h`와 `--safe-top`·`--safe-bottom`을 사용해 iOS 노치·Android 상태바·홈 인디케이터를 침범하지 않는다. 390×844과 430×932에서 가로 스크롤 없이 동작하고, 화면 키보드가 열려도 상단 바와 현재 편집 위치가 접근 가능해야 한다.

### 5.7 강조 배치 OCR — 사진에서 밑줄 모아 담기 (#844, 계획)

§5.6은 한 장씩 **글자만** 추출한다. **종이책에 밑줄/형광펜으로 표시하는 아날로그 독자**(본진)는 표시한 페이지가 여러 장 쌓이므로, 앨범에서 여러 장을 불러와 **각 장의 강조(밑줄/형광펜) 문장만 자동 추출** → 여러 줄로 정리 → 검토 → 일괄 저장한다. **뒷단(검토 큐 + 저장)은 §5.8 텍스트 일괄 입력과 동일 경로를 공유** — 사진이든 붙여넣기든 "문장 배열 → 검토 → 저장"은 같다.

- **진입**: 책 상세(BookDetailModal) **"📷 사진에서 여러 문장 담기"** — §5.8 텍스트 카드 옆(배치류 허브). 홈 앨범 다중 선택은 §5.6의 일반 본문 OCR이며 이 강조 전용 흐름을 재사용하지 않는다.
- **추출 = Gemini Flash vision (핵심)**: Upstage Document OCR은 글자만 읽고 "밑줄 위치"를 모른다(Solar는 텍스트 전용·vision 미지원, 2026-06 확인). 따라서 각 장 사진을 **Gemini Flash vision 서버리스 프록시**(`/api/extract-highlights`)에 보내 **"밑줄·형광펜 등 강조 표시된 문장만 추출"**(JSON 배열). **원문 충실**(병합·교정·요약·번역·환각 금지, §5.6 보정 원칙 재사용). 형광펜·연필·볼펜 모두 의미적으로 인식. Stack Lock: Gemini vision은 [CLAUDE.md AI v9](../../../CLAUDE.md)로 자유(별도 결정 불필요).
- **형광펜 실동작 검증(#1006, 2026-06-26)**: 노랑·분홍·초록 형광펜 + 본문 혼재 합성 페이지(한글)를 배포 워커에 실호출 → 강조 3문장 **정확·원문 그대로 추출, 비강조 본문 3문장 전부 제외**. 색·다중 형광펜 처리 OK(밑줄과 동등). 프롬프트(`HIGHLIGHT_SYSTEM`)가 "강조된 것만"을 명시하고 비강조/머리말/쪽번호 제외를 지시 — 정확성 검증됨.
- **흐름**:
  ```
  [앨범 N장 선택]
     → 각 장: Gemini vision "강조 문장만 추출" (무료 10 RPM → 순차/소량 동시 + 지연, 진행률 표시)
     → 추출된 밑줄 문장들을 여러 줄로 정리
     → BatchQuoteImport 검토 큐(§5.8 공유): 편집/삭제/스킵
     → saveBatchQuotes: myQuotes 일괄 저장 + 완료 요약 1회 (v17: XP·스트릭 변동 없음)
  ```
- **공통 모듈(#848 공유)**: 검토 큐(`BatchQuoteImport`) + 저장(`saveBatchQuotes`)은 텍스트 import와 동일. OCR 배치 신규 코드는 **"앨범 다중 → 각 장 vision 추출 → 문장 배열"** 앞단뿐.
- **rate limit**: 무료 `gemini-2.5-flash` 10 RPM / 1,500 RPD. 수십 장은 순차+지연(또는 소량 동시)으로 조절. 실패 장은 스킵/재시도.
- **지역 precondition flap + 재시도(#1006)**: Gemini 무료 티어(`generativelanguage.googleapis.com`)는 송출 지역에 따라 `400 FAILED_PRECONDITION: "User location is not supported"`을 **간헐** 반환한다(워커가 도는 Cloudflare PoP의 egress 지역에 좌우 — 2026-06-26 실측 동일 사진 5회 중 ~50% 502 flap). 같은 요청이 다른 경로/PoP로 재송출되면 통과하므로 `callVision`은 **최대 3회 재시도**(429·5xx·`FAILED_PRECONDITION` 한정, 350ms×n 백오프, 멱등). 401/403 등 비일시 오류는 즉시 중단.
- **실패 vs 빈 결과 구분(#1006)**: 클라(`runOcrBatch`)는 장별 **비2xx·네트워크 실패 수(`failed`)**를 집계해, 추출 0건일 때 서버/지역 outage(`failed≥N`)는 "추출에 실패했어요 — 잠시 후 다시"로, 강조가 실제로 없을 때만 "더 또렷한 사진으로"를 보여준다(backend 장애를 사진 탓으로 오인 표시 금지). 일부 장 실패+일부 성공이면 찾은 문장은 보여주되 실패 장 수를 안내.
- **환각 안전망**: vision이 없는 문장을 지어낼 위험 → 검토 큐에서 사용자가 확인·삭제로 거른다. (#1006 검증: 비강조 본문은 추출되지 않아 over-extraction 환각은 관측되지 않음.)
- **키 보호/제한**: `GEMINI_API_KEY` **서버에서만**(클라 노출 금지). `VISION_BASE_URL`/`VISION_MODEL`은 wrangler vars + 로컬 `.env`. 이미지 ≤8MB(§5.6 동일). 동일출처만.
- **분석 이벤트**: 이름·발화 상태·허용 속성의 정본은 [analytics.md §3.1.1.1](./analytics.md#3111-ocr-이벤트-계약-1498)를 따른다. 책 상세 강조 이벤트는 현재 미발화 계약이며, 홈 일반 다중 OCR은 원문 없이 성공·실패 분류만 기록한다.

### 5.8 비정형 문장 텍스트 일괄 입력 (#848, 계획)

§5.6/§5.7은 **이미지 → 텍스트**다. 본 건은 **텍스트 → 문장**: 이미 텍스트로 가진 글귀 뭉치(전자책 메모, 타 앱 발췌, 독서 중 적어둔 메모 등)를 **붙여넣으면 개별 "한 문장"으로 분리해 일괄 등록**한다. 2026-06-20 수동 dry-run(헤일메리 43문장 콘솔 주입, 저장 43/실패 0)으로 저장 경로를 실증함 — #848 코멘트 참조.

- **진입**: 한 문장 입력 영역에 "📋 여러 문장 붙여넣기" → 텍스트 영역에 뭉치 붙여넣기.
- **분리 (2단)**:
  - **1차 단순 분리**: 줄바꿈/빈 줄 기준 split + trim + 빈 줄 제거(정형 입력은 이걸로 충분 — dry-run이 이 경로).
  - **2차 LLM 파싱(비정형)**: 문단 섞임·OCR 잡음·구분 없는 뭉치는 서버리스 프록시로 LLM에 문장 배열(JSON) 구조화 요청. **원문 충실 — 병합·교정·요약·번역·환각 금지**(OCR §5.6 보정 원칙 재사용). 짧은 대사·비문·오타도 보존. LLM은 "분리"만, 내용 생성 금지.
- **검토 큐**: 분리 결과를 리스트로 보여주고 **개별 편집/삭제/스킵** → 확정분만 저장(§5.7 리뷰 큐와 동일 UX).
- **제약/검증**: Production DB migration 53은 공개범위와 무관하게 `text` **1~1,000자 CHECK**를 강제한다. 1,000자 초과 조각은 저장 시 앞 1,000 Unicode 문자로 절단하고 비차단 경고를 표시한다. `page`는 미상이면 **null**. 기존 문장과 최종 저장 text 비교로 **중복 스킵(idempotent)**.
- **저장 — 공통 모듈(#844와 공유)**: "다건 → 검토 큐 → myQuotes 일괄 append + 완료 요약 1회"는 §5.7 OCR 배치와 **동일 백엔드 경로**다. v17 경로는 XP·스트릭·둥지 진화를 호출하지 않으며 `handleCheckin` N회 호출도 금지한다. 문장별·배치별 공개범위 selector는 두지 않고 저장 시점의 계정 기본값을 사용하며, 미승인·알 수 없는 값은 더 넓은 공개로 폴백하지 않는다.
- **LLM 엔드포인트**: Gemini Flash 무료 티어 또는 solar-pro3 재사용, **서버리스 프록시**(예: `/api/parse-sentences`). 클라 키 노출 금지([CLAUDE.md Stack Lock](../../../CLAUDE.md)).
- **분석 이벤트**: `text_import_opened`, `text_import_parsed`(method=split|llm, count), `text_import_saved`(book_id, saved, skipped).

#### 텍스트 import 단계 (작은 PR로 분리)

1. **공통 모듈 추출(#844 공유)**: 리뷰 큐 컴포넌트 + 일괄 저장·완료 요약 경로. #844·#848이 함께 소비하며 XP·스트릭·둥지 진화는 포함하지 않는다.
2. **PR — 텍스트 import(1차 단순 분리)**: 붙여넣기 → 줄 기준 분리 → 검토 큐 → 일괄 저장. dry-run이 검증한 경로라 견고한 기준선.
3. **PR — LLM 파싱(2차)**: 비정형 입력에 서버리스 프록시 문장 분리 추가. 원문 충실 프롬프트 + 정확도 점검.
